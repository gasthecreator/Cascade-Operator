# Phase 6.4: latency/error-cascade migrated to mesh.Mitigator

**Date:** 2026-08-31
**Author:** Claude (solo — Cursor unavailable)
**Type:** refactor (interface extension + implementation; no intended behavior change)

## What
- `mesh.Mitigator.ApplyTrip`'s return type changed from `(bool, error)` to
  `(TripOutcome, error)` — `TripOutcome{PrimaryFound bool; AppliedKinds
  []string}`. Needed because latency/error-cascade patches two
  independent object kinds (DestinationRule primary, VirtualService
  secondary) and the caller needs to know which one(s) were actually
  touched this call, to increment the right Prometheus metric label —
  fan-out (one kind only) is updated to the new shape too.
- `internal/mesh/istio/mitigator.go`: latency/error-cascade's `ApplyTrip`/
  `HasManagedEdges`/`ApplyRestoreStep`/`CompleteRestore` implemented,
  covering both object kinds independently (a missing secondary never
  blocks the primary and vice versa, matching PLAN.md §2.6).
- `EffectiveThresholds` (per-edge threshold overrides, PLAN.md §5 Phase 5)
  moved from `internal/controller` to `api/v1alpha1` — the Istio
  Mitigator's restore-step path needs it (the VirtualService secondary's
  timeout target is the *current* effective threshold, re-read every
  restore tick, not a value captured at trip time), and
  `internal/controller` already imports `internal/mesh/istio`, so keeping
  it in `internal/controller` would have created an import cycle.
  `api/v1alpha1` is the shared ancestor both packages already import.
- `internal/controller/mitigate.go` and `restore.go`'s latency/error
  functions rewritten to delegate to `r.mitigator()`, mirroring fan-out's
  Phase 6.3 shape exactly.

## Why
Latency/error-cascade is the second signature migrated (after fan-out,
Phase 6.3) and the harder of the remaining two — it has a secondary
object kind, unlike fan-out. Retry storm (also two object kinds, plus
the JSON-Patch-vs-merge-patch zero-value subtlety) is still not migrated
— its restore path needs its own dedicated, careful pass.

## How
- `TripOutcome` is a real interface widening, not scope creep: fan-out's
  Phase 6.3 implementation already needed *a* Kind string for its metric
  ("DestinationRule"), it just didn't need to report it conditionally
  since fan-out only ever has one candidate. Latency/error-cascade's two
  independent, potentially-absent objects made the single-bool return
  insufficient — extending the type now, while only two of three
  signatures use it, is cheaper than a second interface change once
  retry storm (which has the identical two-kind shape) is migrated next.
- `KindDestinationRule`/`KindVirtualService` exported from
  `internal/mesh/istio`, matching `internal/controller/metrics.go`'s
  existing private `kindDestinationRule`/`kindVirtualService` constants'
  *string values* exactly (both literally `"DestinationRule"`/
  `"VirtualService"`) — same Prometheus label values as before migration,
  by construction, not by coincidence.
- `EffectiveThresholds`'s move is a pure relocation: same logic, same
  tests (moved to `api/v1alpha1/thresholds_test.go`, using local literal
  FQDN constants instead of `internal/controller`'s private ones, since
  the test can no longer reach across package boundaries — cosmetic only).

## Files touched

- `internal/mesh/istio/mitigator.go` — latency/error-cascade added;
  `KindDestinationRule`/`KindVirtualService` constants; `drEdge`/
  `listManagedDREdges` renamed from `fanOutEdge`/`listFanOutEdges` (now

- `internal/controller/fanout_mitigate.go` — updated to the new
  `TripOutcome` shape
- `internal/controller/mitigate.go`, `restore.go` — latency/error-cascade
  delegates to `r.mitigator()`
- `api/v1alpha1/thresholds.go`, `thresholds_test.go` (new — moved from
  `internal/controller/thresholds.go`/`thresholds_test.go`, deleted)

## Testing
- `go build ./...`, `go vet ./...`, `gofmt -l .` — clean.
- `go test ./... -race` — full suite passes, **including every existing
  latency/error-cascade test unchanged** (`restore_test.go`,
  `cascadepolicy_controller_test.go`'s latency/error tests, the
  three-signature dispatch-isolation tests, and the Phase 10 property
  tests in `statemachine_rapid_test.go`) — all drive through the real
  `Reconcile` path against a fake client, so passing unmodified is real
  evidence of preserved behavior.
- `make lint` — 0 issues.
- **Live-verified**: `make test-integration` against the live dev Kind
  cluster — all three signatures' wire-format tests pass, including
  `TestLatencyErrorCascadeTripAndRestoreWireFormat` through the new path.
  Also ran the real `latency-error-cascade` k6 scenario against the live
  cluster directly (`hack/capture-episode.sh`), confirming a genuine
  trip → mitigate → restore cycle end to end, not only the automated
  suites.

## Follow-ups / known gaps
- Retry storm is still not migrated — the last of the three signatures,
  and the one with the most subtlety (the zero-value JSON-Patch-vs-merge-
  patch fix this project spent real effort getting right). Its own slice.
- Once retry storm is migrated, `internal/controller/restore.go`'s
  `listManagedDestinationRuleEdges`/`managedDREdge` and
  `retry_restore.go`'s `listManagedVirtualServiceEdges`/`managedVSEdge`
  become fully dead code and should be deleted, along with the
  `internal/mesh/istio` package's own temporary duplicate copies
  collapsing to a single canonical implementation.
