# Phase 6.3: Mitigator interface + fan-out amplification migrated

**Date:** 2026-08-31
**Author:** Claude (solo — Cursor unavailable)
**Type:** refactor (new interface + implementation; no intended behavior change)

## What
- `mesh.Mitigator` interface added to `internal/mesh/mesh.go`: `ApplyTrip`,
  `HasManagedEdges`, `ApplyRestoreStep`, `CompleteRestore` — scoped
  deliberately narrow (see its own doc comment): it owns only mesh-specific
  object mutation, not `DependencyObjectMissing`, metrics, notifications,
  or `status.Phase`/`RestoreStep` transitions, which stay in
  `internal/controller` regardless of which mesh backs a policy.
- `internal/mesh/istio/mitigator.go`: Istio's implementation, for
  **fan-out amplification only**. Latency/error-cascade and retry storm
  (both of which manage a secondary object kind alongside their primary)
  are not migrated — calling this interface with either of those
  `SignatureType`s returns an explicit error, which is safe today because
  `internal/controller` never does that yet, not because it's unreachable
  in principle.
- `internal/controller/fanout_mitigate.go` and `fanout_restore.go`
  rewritten to delegate to `r.mitigator()` instead of calling
  `internal/mitigation` and `r.Get`/`r.Update` directly. External shape
  (function names, `Reconcile`'s dispatch, `restore.go`'s
  `forceCompleteOutgoingRestore` handoff case) unchanged.

## Why
PLAN.md §5 Phase 6 calls for a `Mitigator` interface as the larger half of
the mesh-adapter work (`QueryBuilder`, Phase 6.1, only covers detection
queries). Migrating all three signatures in one pass would mean touching
`internal/mitigation`'s 10 files and ~6 controller files simultaneously,
in a system whose correctness this whole project has been unusually
careful about (the retry-storm zero-value bug thread, the signature-
handoff fix). Fan-out went first because it is the simplest case — one
managed object kind, no secondary, no two-object-kind restore
bookkeeping — making it possible to prove the interface shape is sound
against a real, fully-tested signature before committing to the same
shape for the two harder cases.

## How
- `ApplyTrip`'s `found bool` return replaces the old code's direct
  `setDependencyMissing`/`clearDependencyMissing` calls inside the
  mitigate function — those stay in `internal/controller`, now driven by
  the return value instead of being called from inside the (soon to be
  mesh-agnostic) mitigate function itself.
- **Real regression caught before it shipped, not after**: the original
  `completeFanOutRestore` returned early in `DetectOnly` mode, *before*
  reaching `restorationsCompletedTotal.Inc()`/`r.notifyRestore(...)` — so
  DetectOnly never counted or notified a restore completion. My first
  rewrite called `notifyRestore` unconditionally, changing that behavior.
  Caught by re-reading the diff against the original function's control
  flow before considering the slice done — fixed to gate both calls on
  `Mode != DetectOnly`, matching the original exactly.
- `internal/mesh/istio/mitigator.go`'s own edge-listing
  (`listFanOutEdges`) intentionally duplicates
  `internal/controller/restore.go`'s `listManagedDestinationRuleEdges` —
  latency/error-cascade's own restore path still calls that controller-
  package function directly, so it can't be deleted or moved yet without
  breaking unmigrated code. Temporary, resolves naturally once the other
  two signatures are migrated (see `internal/mesh/istio/mitigator.go`'s
  own doc comment).

## Files touched
- `internal/mesh/mesh.go` — `Mitigator` interface
- `internal/mesh/istio/mitigator.go` (new)
- `internal/controller/cascadepolicy_controller.go` — `Mitigator` field,
  `mitigator()` default-when-nil helper (mirrors `queryBuilder()`)
- `internal/controller/fanout_mitigate.go`, `fanout_restore.go` — rewritten
  to delegate
- `internal/controller/restore.go` — `forceCompleteOutgoingRestore`'s
  fan-out case updated to the new `HasManagedEdges`/`completeFanOutRestore`
  signatures

## Testing
- `go build ./...`, `go vet ./...`, `gofmt -l .` — clean.
- `go test ./... -race` — full suite passes, **including every existing
  fan-out test unchanged** (`fanout_mitigate_test.go`,
  `fanout_restore_test.go`, and the three-signature dispatch-isolation
  tests in the latter) — all of them drive through the real `Reconcile`
  path against a fake client, never the internal function signatures
  directly, so their passing unmodified is real evidence this refactor
  preserved exact behavior (annotation handling, restore-ramp math,
  cross-signature field isolation, DetectOnly metrics/notify
  suppression), not just that it compiles.
- `make lint` — 0 issues.
- **Live-verified**: re-ran the fan-out k6 scenario against the live dev
  Kind cluster with the refactored code (`hack/capture-episode.sh
  fanout-amplification`) — confirmed trip and restore still work
  end-to-end against a real cluster, not only the fake-client suite.

## Follow-ups / known gaps
- Latency/error-cascade and retry storm are not migrated — this is
  explicitly Phase 6.3's whole scope, not an oversight. Migrating them
  is harder: each manages a secondary object kind on a different Istio
  type, and retry storm's restore path in particular has the JSON-Patch-
  vs-merge-patch zero-value subtlety this project spent real effort
  getting right — that migration needs its own dedicated, careful pass,
  not a quick follow-on to this one.
- Once all three signatures are migrated, `internal/controller/restore.go`'s
  `listManagedDestinationRuleEdges`/`managedDREdge` and
  `retry_restore.go`'s `listManagedVirtualServiceEdges`/`managedVSEdge`
  become dead code and should be deleted, along with
  `internal/mitigation`'s Istio-typed functions moving fully behind the
  interface (today they're still called directly by the two unmigrated
  signatures).
