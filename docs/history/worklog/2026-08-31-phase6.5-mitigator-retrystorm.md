# Phase 6.5: retry storm migrated to mesh.Mitigator (last of three signatures)

**Date:** 2026-08-31
**Author:** Claude (solo — Cursor unavailable)
**Type:** refactor (interface implementation + dead-code removal; no intended behavior change)

## What
- `internal/mesh/istio/mitigator.go`: retry storm's `ApplyTrip`/
  `HasManagedEdges`/`ApplyRestoreStep`/`CompleteRestore` implemented —
  the VirtualService primary (`retries.attempts`) and DestinationRule
  secondary (`connectionPool.http.maxRetries`), independently patched/
  restored, preserving the exact patch mechanism each field needs:
  JSON Patch for the trip write, JSON merge patch for every restore
  write on the VirtualService (never typed `Update()` — the reason the
  whole zero-value bug thread exists), and deliberately-typed `Update()`
  for the DestinationRule secondary's restore (investigated in Phase 5,
  found not to be the same bug).
- `internal/controller/retry_mitigate.go`, `retry_restore.go` rewritten
  to delegate to `r.mitigator()`, mirroring the shape Phases 6.3/6.4
  already established for the other two signatures.
- **Dead code removed**: `internal/controller/restore.go`'s
  `managedDREdge`/`listManagedDestinationRuleEdges` and
  `retry_restore.go`'s former `managedVSEdge`/`listManagedVirtualServiceEdges`
  deleted — with all three signatures migrated, nothing in
  `internal/controller` calls them anymore. `internal/mesh/istio`'s own
  `drEdge`/`listManagedDREdges` and `vsEdge`/`listManagedVSEdges` are now
  the single canonical implementation, not a temporary duplicate.

## Why
This is the last of the three signatures and the one flagged throughout
Phases 6.3/6.4 as needing its own dedicated pass — not because the
Mitigator interface itself needed to change again (it didn't:
`ApplyTrip`'s `TripOutcome` shape, designed in Phase 6.4 for latency/
error-cascade's two independent object kinds, fit retry storm's
identical two-kind shape without modification), but because retry
storm's actual patch-writing code is the most fragile in the project —
the entire session-spanning zero-value bug thread (JSON Patch vs. merge
patch, Istio's own Pilot translation limit on `maxRetries`) lives here.
Getting the migration byte-for-byte identical to the pre-migration
behavior mattered more for this signature than for the other two.

## How
- Reused `listManagedDREdges`/`listManagedVSEdges` as-is (already
  generic, not signature-specific — built in Phase 6.4) rather than
  writing retry-storm-specific listing helpers.
- Moved the exact patch-mechanism choices verbatim: `client.RawPatch`
  with `types.JSONPatchType` for the trip write
  (`RetryStormAttemptsJSONPatch`), `types.MergePatchType` for the
  secondary's trip (`RetryStormMaxRetriesMergePatch`) and every restore
  write on the VirtualService (`RetryStormRestoreStepMergePatch`,
  `RetryStormRestoreCompleteJSONPatch` — the latter is a merge patch
  despite its name, a pre-existing naming quirk not touched here), and
  plain `Update()` for the DestinationRule secondary's restore
  (`ApplyRetryStormConnectionPoolRestoreStep`/
  `CompleteRetryStormConnectionPoolRestore`) — no mechanism changed,
  only who calls it.

## Files touched
- `internal/mesh/istio/mitigator.go` — retry storm added
- `internal/controller/retry_mitigate.go`, `retry_restore.go` — delegate
  to `r.mitigator()`
- `internal/controller/restore.go` — dead `managedDREdge`/
  `listManagedDestinationRuleEdges` removed; `forceCompleteOutgoingRestore`'s

  new signature
- `internal/controller/fanout_restore.go`, `retry_storm_test.go` — stale
  comments referencing the deleted helpers updated

## Testing
- `go build ./...`, `go vet ./...`, `gofmt -l .` — clean.
- `go test ./... -race` — full suite passes, **including every existing
  retry storm test unchanged** (`retry_storm_test.go` — the file that
  directly encodes the zero-value bug fix's regression coverage) — all
  drive through the real `Reconcile` path against a fake client, so
  passing unmodified is the strongest available evidence this migration
  didn't reintroduce the bug it exists to prevent.
- `make lint` — 0 issues.
- **Live-verified, and unusually thorough by accident**:
  `make test-integration` against the live dev Kind cluster —
  `TestRetryStormTripAndRestoreWireFormat` passes, with the raw
  apiserver JSON showing the exact `"attempts":0`/`"maxRetries":1` values
  the whole zero-value bug thread was about, through the new path. A
  live k6-driven `retry-storm` scenario run then happened to exercise
  the hardest possible case for free: a genuine cross-signature handoff
  (retry storm tripped first with real evidence, then handed off to
  latency/error-cascade on the same host mid-episode). Confirmed live
  that `forceCompleteOutgoingRestore` correctly force-completed retry
  storm's restore — both object kinds restored to true original values,
  both of its own annotations stripped — before latency/error-cascade's
  trip applied, with no orphaned state left behind.
